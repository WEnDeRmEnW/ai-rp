# Letopis — план тотального улучшения

> Составлен по реальному коду репозитория. Каждый шаг — отдельное задание для Codex.
> **Золотое правило: после каждого шага прогонять `npm test && npm run lint && npm run build` — 272 теста должны оставаться зелёными.**

## 1. Ускорение генерации контента (главный эффект)

### 1.1. Стриминг ответа нарратора
Сейчас в `server/provider.ts` ответ ждётся целиком (таймаут до 300 секунд) — игрок смотрит на спиннер. Добавить `stream: true` для стадии `narrative` и отдавать текст в UI по мере генерации через SSE. Валидацию и коммит состояния оставить после полного ответа.
**Ожидаемый эффект: воспринимаемая скорость хода вырастает в разы.**

### 1.2. Сократить промпты (405 КБ в `server/prompts.ts`)
Самый большой резерв реальной скорости: чем больше входных токенов, тем дольше и дороже каждый вызов.
- Провести аудит: какие секции промптов реально влияют на качество (проверять на `prompts.test.ts`).
- Убрать повторяющиеся инструкции между директорами (событий/хода/аудиторов) в общий короткий блок.
- Отправлять в контекст только релевантные секции мира для текущей сцены, а не весь мир.

### 1.3. Кэширование промптов провайдера
Системные промпты почти не меняются между ходами. Для OpenAI/DeepSeek/OpenRouter включить prompt caching: стабильную часть промпта размещать первой, изменяемый контекст — в конце. Снижает задержку и стоимость на 50–90% на повторных вызовах.

### 1.4. Параллелить независимые вызовы
- Кандидаты нарратива: генерировать параллельно (`Promise.all`), а не по очереди.
- Аудиты (непрерывность / агентность / последствия) — независимы друг от друга, запускать параллельно.
- В 6-стадийной генерации мира: стадии 3 (NPC) и 4 (легендариум) во многом независимы после стадии 2 — проверить зависимости и запускать конкурентно.

### 1.5. Разные модели для разных стадий
Стадии `service` не требуют топ-модели. Добавить в `ProviderConfig` опциональную `serviceModel` — дешёвую/быструю модель для служебных вызовов, основную — для нарратива и мира.

### 1.6. Точечные фиксы в `provider.ts`
- `inferStage()` угадывает стадию регексами по русскому тексту системного промпта — хрупко, ломается при правке промптов. Передавать `stage` явно из оркестратора и удалить эвристику.
- В `completeJson()` при ремонте обрезанного JSON в контекст добавляется весь предыдущий (огромный) ответ. Ограничить вставляемый хвост последними 4–8k символов.

## 2. Рефакторинг монолитов (по одному за итерацию)

| Файл | Размер | Что сделать |
|---|---|---|
| `server/prompts.ts` | 405 КБ | Разбить на `server/prompts/{world,turn,events,audits,interface}.ts` |
| `server/orchestrator.ts` | 170 КБ | Разбить на пайплайн: `context.ts`, `simulation.ts`, `turn-director.ts`, `audits.ts`, `commit.ts` |

Правила: один файл за итерацию; только перемещение кода с ре-экспортом из старого пути (импорты и тесты не меняются); тесты после каждого шага.

## 3. Дизайн: полное обновление без поломок

1. **Разбить `styles.css`** на модули по компонентам: `styles/{tokens,layout,story,inspector,dialogs,composer}.css`. Сначала — чистое перемещение без изменения правил.
2. **Дизайн-токены**: вынести все цвета/отступы/радиусы/тени в CSS-переменные в `tokens.css` (частично уже есть: `--accent`, `--gold`). После этого редизайн — замена одного файла.
3. **Чистка мёртвого CSS**: PurgeCSS в режиме отчёта (не автоудаления!), удалять руками с проверкой UI.
4. **Типографика чтения**: межстрочный интервал прозы 1.7–1.8, ширина колонки 65–75 символов, плавная прокрутка к новому сообщению.
5. **Скелетоны вместо спиннера** при генерации хода + прогресс стадий (данные уже есть — `operationProgress`).
6. В `src/App.tsx` заменить прямые чтения `window.innerWidth` в рендере на хук `useMediaQuery` — сейчас поведение не обновляется при резайзе/повороте экрана.

## 4. Убрать ненужное

- `.infinity-test*.json` (~200 КБ) из корня → в `tests/fixtures/` (сначала `git grep infinity-test`, чтобы поправить пути) или в `.gitignore`, если это локальные артефакты.
- Проверить `server/live-*-smoke.ts` — если это ручные скрипты, перенести в `scripts/` и описать в README.
- После разбиения `prompts.ts` найти неиспользуемые экспорты: `npx ts-prune`.
- Добавить `LICENSE` (например MIT — решение владельца репозитория).
